`LosslessConfig` in `dataplane/src/node/config.rs` owns the runtime defaults for
the block-first lossless session subsystem.

## Status

This page documents the current shipped implementation.

The design reference for the rewrite lives in
`plans/fec-lossless-design.md`.

## Glossary

| Term | Meaning |
|------|---------|
| `Session` | One sender/receiver transfer identified by `session_id`. |
| `Block` | The canonical transfer unit in both plain and FEC modes. |
| `Symbol` | A FEC payload fragment within a block. Plain mode does not use symbols. |
| `Manifest` | Startup metadata that fixes `block_size`, `total_bytes`, `total_blocks`, and mode. |
| `BlockAck` | Receiver acknowledgement for one completed block. |
| `BlockStatus` | Receiver request for additional FEC symbols for one incomplete block. |

## Fields

| Field | Default | Description |
|-------|---------|-------------|
| `default_block_size` | `8500` | Default transfer block size in bytes. |
| `data_bucket` | `None` | Optional token bucket for sender pacing. |
| `ready_grace_ms` | `1500` | Grace window before the sender opens the data gate when not all receivers have sent `Ready`. |
| `fec_enabled` | `false` | Global FEC enable switch. Plain mode remains the default. |
| `fec_default_symbols_per_block` | `32` | Default `symbols_per_block` for runtime-derived FEC manifests. Must be greater than zero. |
| `fec_default_tree_ids` | `[0]` | Ordered unique tree ID list used for FEC symbol striping. Must be non-empty. |

## Runtime Behavior

### Plain Mode

Plain mode is the default. The sender emits `BlockData` on a single tree and
the receiver completes each block with `BlockAck`.

There is no cumulative ACK state, no sliding window, and no sender-side ACK
timeout.

### FEC Mode

FEC is optional. When enabled, the sender emits `BlockSymbol` packets for each
block using the manifest’s `symbols_per_block`.

The scheduler is source-first:

- it sends the next source symbol before any extra symbol
- it sends extra symbols only after the receiver reports `BlockStatus`
- extra output stays `BlockSymbol`; there is no separate repair frame

The receiver sends:

- `Ready` after a valid manifest
- `BlockAck` when a block is reconstructed
- `BlockStatus` when `Eot` arrives and a block still needs symbols

## Multi-Tree And Backpressure

`tree_id` is part of the FEC symbol wire format, but sender-local tree lanes are
not part of the design.

For FEC senders:

- tree IDs must already be configured as a sorted unique set
- multi-tree mode requires `Feature::Sequential`
- multi-tree mode requires `channel_backpressure=true`
- backpressure is observed at processor ingress via non-blocking submission

When a symbol submission for a tree returns `WouldBlock`, that tree is treated
as backpressured for that send attempt and the sender tries another configured
tree.

## Example

```toml
[lossless_runtime_config]
default_block_size = 8500
ready_grace_ms = 1500
fec_enabled = false
fec_default_symbols_per_block = 32
fec_default_tree_ids = [0]

# Optional pacing
# [lossless_runtime_config.data_bucket]
# rate = 50_000_000
# bucket_size = 200_000
```

## Notes

Tune `default_block_size` alongside MTU and pacing constraints. The shipped
default of `8500` bytes targets jumbo-frame environments.

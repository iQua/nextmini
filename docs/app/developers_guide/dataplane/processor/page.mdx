## Processor

**The Role of `ProcessorManager`**: This struct is responsible for creating,
starting, and managing the lifecycle of all the `Processor` instances.

The `ProcessorManager` calls `spawn_processors`:

```rust
    // In strato/dataplane/src/dataplane/processor.rs
    // Inside impl ProcessorManager

    async fn spawn_processors(&mut self){
        // Loop to create one task for each processor needed
        for i in 0..self.receiver_rxs.len(){
            // Get the RECEIVING end of the MPSC channel for this processor
            let receiver_rx = self.receiver_rxs[i].clone();
            let shutdown_flag = Arc::new(AtomicBool::new(false));

            let flg = shutdown_flag.clone();
            let table = self.routing_table.clone();
            let senders = self.context.reproduce_senders().await;
            let tun_writers = self.context.get_tun_writers(i).await;
            let stream2routes = self.stream2routes.clone();
            let stream_counters = self.stream_counters.clone();
            let metrics_tx = self.context.get_metrics_tx();
            let handle = tokio::task::spawn(async move{
                let mut proc = Processor::new(receiver_rx, table, senders, tun_writers, stream2routes, stream_counters,flg, metrics_tx);
                proc.run().await;
            });
            self.proc_shutdown_flags.push_back(shutdown_flag);
            self.proc_handles.push_back(handle);
        }
    }
```

## The connection between TunReader and Processor

**Channel Creation and Distribution (Setup Phase)**:
*   When the system starts (e.g., in `Controller::connect`), the `Context` is created.
*   `Context::get_processor_txs` and `Context::get_processor_rxs` are called. **Key Point**: Inside these functions, `tokio::sync::mpsc::channel(INTERNAL_Q_SIZE)` is called to create **pairs** of `(Sender<Packet>, Receiver<Packet>)`.
*   The `SenderLoadBalancer` (created within `TunReader` or `NodeReceiver`) gets clones of these `Sender<Packet>`s and stores them in `self.txs`.
*   The `ProcessorManager` gets the **corresponding** `Receiver<Packet>`s and stores them in `self.receiver_rxs`.
*   **At this point, `SenderLoadBalancer` holds the sending ends of the channels, and `ProcessorManager` holds the receiving ends.**

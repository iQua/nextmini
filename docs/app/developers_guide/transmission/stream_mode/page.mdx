## Number of TUN interfaces in stream mode

In stream mode, only one TUN interface is created per node, regardless of the number of routes. 
This is different from interface mode, which creates multiple interfaces (one per path).

Instead of routing packets through different TUN interfaces,
the system assigns different TCP/UDP streams to different paths.

In `context.rs`:

The TUN device type is now `tun::AsyncDevice` instead of the old `tun::platform::linux::Device`.


In `config.rs`:

```rust
let mut num_interfaces = 1;
if multi_path_method == "interface" {
    // We are using multiple interfaces for our multi-path method. Set the number of local interfaces to
    // the number of paths
    num_interfaces = data["num_interfaces"].as_usize().expect(
        "Invalid controller message: Using interface multipath method, should have num_interfaces field");
}

```

Which means in "stream" mode, there is only one local interface in each device. 
In the old tun version, we will have 256 queues and 256 tun writers and readers.
For tun 0.7, in `processor.rs`, 
the code expects tun_writers to be a collection that can be indexed by an interface ID (if_id) extracted from the flow ID, 
but in the actual implementation, each processor might only have a single TUN queue.


### processor

In `processor.rs`, when processing packets:

```rust
pub struct Context {
    // ...
    tun_writers: Arc<RwLock<Vec<Vec<TunWriter>>>>,
    // ...
}
```

How it accessed:

```rust
pub async fn get_tun_writers(&self, queue_id: usize) -> Vec<TunWriter> {
    //Get a copy writers for the corresponding to a queue in multi queue TUN TAP
    self.tun_writers.read().await.get(queue_id)
        .expect("Criticial Error: Attempting to obtain TUN queue that doesn't exists. Check to see if tunqueues are created successfully")
        .clone()
}

```
Access the outer vector using `queue_id` and returns the entire inner vector.

Here's a mismatch:

```rust
let if_id = (&packet.flow_id & FLOW_ID_IF_MASK) >> 8;
self.tun_writers.get_mut(if_id as usize)
    .expect("Destination interface {if_id} doesn't exist...")
    .write_packet(packet).await;
```
The processor expects to access different TUN writers based on an interface ID extracted from the flow ID, 
but the implementation only creates one writer per TUN device, causing potential index out-of-bounds errors.

The most important point about [`queue`](https://docs.rs/tun/0.7.18/tun/struct.Configuration.html#method.queues) in tun 0.7 docs:
```rust
pub fn queues(&mut self, value: usize) -> &mut Self
// 👎Deprecated since 0.7.0: The queues will always be 1.
```

In "stream" mode, routing decisions should be made by the routing table based on stream IDs, 
not by selecting different TUN devices.

And in the function:

```rust
pub async fn start_tun_device(
    &mut self,
    configs: &LocalConfigs,
    controller_configs: &ControllerConfigs,
    tun_devs: Vec<tun::AsyncDevice>,
) {
    let mut guard = self.tun_writers.write().await;
    for dev in tun_devs {
        let receiver_txs = self.get_processor_txs().await;
        let writer_qs = start_tun_device(controller_configs, dev, receiver_txs);
        let mut i = 0;

        for q in writer_qs {
            if let Some(qs) = guard.get_mut(i) {
                qs.push(q);
            } else {
                // If q doesn't exist, initialize the vector of queues
                for _ in 0..configs.num_packet_processors {
                    guard.push(vec![]);
                }
                guard.get_mut(i).unwrap().push(q);
            }
            i += 1;
        }
    }
}
```

First Dimension (Outer Vector):
- Represents interface queues or processing units

- In the actual implementation, only index 0 is used, since only one writer is added per device

- This doesn't match the processor's expectation of being able to index by if_id


*The mismatch* occurs because:
The processor tries to select a TUN writer based on an interface ID extracted from the flow ID.
But the implementation only creates one writer per TUN device, not mapping to different interface IDs.



The actual creation happens in the `create_tun_devices` function in `local_interface.rs`:

```rust
pub fn create_tun_devices(
    configs: LocalConfigs,
    controller_configs: ControllerConfigs,
) -> Vec<AsyncDevice> {
    let mut devs = Vec::new();
    for i in 0..controller_configs.num_interfaces {
        let mut ipv4_addr = controller_configs.strato_address.clone();
        ipv4_addr.2 += i as u8;
        let ipv4_mask = controller_configs.strato_mask;

        let mut config = Configuration::default();

        config
            .address(ipv4_addr)
            .netmask(ipv4_mask)
            .mtu(configs.mtu)
            .up();

        #[cfg(target_os = "linux")]
        config.platform_config(|config| {
            config.ensure_root_privileges(true);
        });

        let dev = tun::create_as_async(&config).expect("Failed to create tun_device");
        println!("Successfully created tun device.");
        devs.push(dev);
    }
    devs
}
```

## Start tun device

### In the main branch

```rust
pub fn start_tun_device(
    controller_configs: &ControllerConfigs,
    dev: AsyncDevice,
    receiver_txs: Vec<Sender<Packet>>,
) -> Vec<TunWriter> {
    let dev_arc = Arc::new(Mutex::new(dev)); // Wrap device in Arc<Mutex> for mutable access

    let mut writer_qs = vec![];

    // Create a single reader and writer
    let txs = receiver_txs.clone();

    let mut reader = TunReader::new(dev_arc.clone(), txs);
    let method = controller_configs.multi_path_method.clone();

    tokio::spawn(async move {
        reader.start_reading(method).await;
    });

    let method = controller_configs.multi_path_method.clone();
    writer_qs.push(TunWriter::new(dev_arc, method));

    writer_qs
}
```

256 queues are created.

### The tun-upgrade branch

```rust
pub fn start_tun_device(
    controller_configs: &ControllerConfigs,
    dev: AsyncDevice,
    receiver_txs: Vec<Sender<Packet>>,
) -> Vec<TunWriter> {
    let dev_arc = Arc::new(Mutex::new(dev)); // Wrap device in Arc<Mutex> for mutable access

    let mut writer_qs = vec![];

    // Create a single reader and writer
    let txs = receiver_txs.clone();

    let mut reader = TunReader::new(dev_arc.clone(), txs);
    let method = controller_configs.multi_path_method.clone();

    tokio::spawn(async move {
        reader.start_reading(method).await;
    });

    let method = controller_configs.multi_path_method.clone();
    writer_qs.push(TunWriter::new(dev_arc, method));

    writer_qs
}
```

The master branch version iterated over n_queues = configs.num_packet_processors, pushing a writer for every queue. 
That for-loop is gone in the upgrade, leaving only the one push.

Instead of multiple FDs polled in parallel, all writers share the same AsyncDevice under a mutex.
